3. RULE FORMAT (SUGGESTED)
--------------------------
Keep rules declarative so they are auditable and easy to cite in the report.

rules/powershell_encoded.yml example:

  id: RULE-PS-001
  title: PowerShell encoded or download command
  attack: T1059.001
  severity: high
  applies_to_process: [powershell.exe, pwsh.exe]
  conditions:
    any:
      - command_line_regex: "(?i)-enc(odedcommand)?\\s+[A-Za-z0-9+/=]{20,}"
      - command_line_regex: "(?i)-e\\s+[A-Za-z0-9+/=]{20,}"
      - command_line_regex: "(?i)(downloadstring|invoke-webrequest|iwr|curl|wget)"
  reason: "PowerShell used with encoded payload or remote download"
  references:
    - https://attack.mitre.org/techniques/T1059/001/

Use these condition types (keep it small and explainable):
  process_is:      exact image name match
  parent_is:       exact parent image name match
  command_line_regex: case-insensitive regex over command_line
  path_regex:      regex over command_line or image path
  any / all / not: boolean composition

Every rule must have: id, title, attack, severity, reason, conditions.
Rule ids must be stable - I will reference them in the results table.

5. OUTPUT CONTRACT (CRITICAL FOR COMPARABILITY)
-----------------------------------------------
results/rules_test.csv and results/rules_holdout.csv must contain ONE ROW PER
EVENT, including events that matched nothing. Columns:

  record_id, matched_any, n_rules_matched, matched_rule_ids, reasons,
  attack_ids, severity_max

  matched_any       1/0 (or True/False); 1 if at least one rule matched
  matched_rule_ids  semicolon-separated ids, empty string if none
  reasons           semicolon-separated reason texts, empty string if none
  attack_ids        semicolon-separated ATT&CK ids, empty string if none

Do not drop negative rows. Recall cannot be computed without them.

results/rules_long.csv (optional):
  record_id, rule_id, matched, reason, attack_id, severity
  One row per (event, rule) combination that matched.

results/rules_summary.csv:
  dataset,model,threshold,precision,recall,f1,fpr,tp,fp,fn,tn,notes
  dataset   = "original" (E1 uses the original, not the debiased dataset)
  model     = "Rules-only (deterministic)"
  threshold = "n/a" (or empty)
  Fill precision/recall/f1/fpr at EVENT level (any rule match = positive).
  Rows for both "test" and "holdout" are welcome; holdout is malicious-only so
  FPR is not defined there - leave it blank and put the count in notes.

7. HOW YOUR OUTPUT PLUGS INTO THE HYBRID
----------------------------------------
After E1, I will combine rule evidence with the frozen ML models in one of two
ways (decided on validation only, never test):
  a) feature-level: matched_any, n_rules_matched and per-rule binaries added

Either way I need, for every test and holdout record_id:
  matched_any, n_rules_matched, matched_rule_ids, severity_max.
That is why the per-event output contract above matters. Rule ordering in the
CSV does not matter, but record_id must match the dataset exactly.


8. LEAKAGE AND FAIRNESS CHECKLIST
---------------------------------
[ ] Rules never read label, mitre_technique, command_source, rule_category,
    dataset_origin, record_id patterns or file paths that encode the answer.
[ ] No rule keyed on the WLGT_ / wlgtRef / wlgt_ markers (these are synthetic
    benign markers; using them would be leakage).
[ ] No tuning on test or holdout. Development use of train/val is fine.
[ ] All test and holdout record_ids appear exactly once in your CSV.
[ ] Rule ids, titles, ATT&CK ids and reasons are written down in rules/README.txt.
[ ] The engine is deterministic: same input, same output, no randomness.

The dataset's benign rows contain synthetic marker strings (WLGT_Task_*,
-wlgtRef:*, wlgt_*). They appear in 62.65% of benign rows and 0.06% of
malicious rows. Do NOT write rules that match them.
